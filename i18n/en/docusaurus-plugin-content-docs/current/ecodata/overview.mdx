## Automated econometrics analysis pipeline across triple runtime

Instead of manually exporting raw files into spreadsheets and configuring separate statistical software, EcoData provides a seamless, closed-loop econometrics pipeline from data preparation to reproducible script export.

<EconometricsPipelineSvg />

### Four closed-loop analysis stages

1. **Data ingestion and transformation:**
   - Automatic multi-source data merging based on entity identifiers ($i$) and time periods ($t$).
   - Automated stationarity checks (Augmented Dickey-Fuller and Phillips-Perron tests), first-differencing, log transformations, and lag creation.
2. **Model specification:**
   - Supports **105 econometric models across 12 specialized families**: Linear regressions (OLS, WLS, GLS), Panel data (Fixed Effects, Random Effects, Pooled OLS, 2SLS), Dynamic Panel GMM (Arellano-Bond, Blundell-Bond), Time Series (VAR, VECM, ARDL), Binary choice models (Logit, Probit, Tobit), Survival analysis, Spatial econometrics, and Causal inference (Difference-in-Differences, Synthetic Control).
3. **Parallel execution across triple runtime (Python / R / Stata 18 MP):**
   - EcoData's analytical engine executes models synchronously across three computational environments:
     - **Python Runtime:** Utilizes `statsmodels`, `pandas`, and `linearmodels` for high computational throughput and AI interoperability.
     - **R Runtime:** Leverages `tidyverse`, `plm`, and `fixest` for high-dimensional fixed-effect estimations.
     - **Stata 18 MP Runtime:** Powered by the multi-core C-engine of Stata 18 MP, representing the gold standard of empirical accuracy for Q1 Scopus and FT50 journals.
4. **Hypothesis testing and replication packages:**
   - Comprehensive automated diagnostic battery: Multicollinearity ($VIF$), Heteroskedasticity (White test, Breusch-Pagan test), Autocorrelation (Durbin-Watson, Breusch-Godfrey test), and specification Hausman tests.
   - Formatted academic regression tables: APA 7th, Chicago 8th, Harvard 2008, IEEE 2008, and MLA 7th.
   - Complete, executable replication bundles: `.do` (Stata), `.R` (R), and `.py` / `.ipynb` (Python) files packaged with processed datasets.

## EcoData MCP Server architecture with 37 specialized AI tools

The Model Context Protocol (MCP) is an open standard allowing large language models to interact securely with external tools and databases. EcoData is the first platform in the region to launch a production **EcoData MCP Server** featuring **37 specialized AI tools**, enabling AI assistants to explore, retrieve, and estimate empirical models without manual code writing.

<McpServerFlowSvg />

### Featured tools catalog

Among the 37 specialized tools, key capabilities include:

- `search_indicators_unified`: Semantic multilingual search across 200,000+ indicators.
- `query_macro_data_unified`: One-step multi-dimensional retrieval with verified metadata.
- `inspect_series_metadata`: Deep inspection of calculation methodologies, issuing agencies, units, and update cadences.
- `run_econometrics_regression`: Direct natural-language execution of OLS, Panel, and GMM models.
- `export_replication_bundle`: Automatic packaging of Stata, R, and Python code bundles.
- `query_customs_trade_data`: Granular export-import data querying by HS code, partner nation, and province.
- `query_corporate_financials`: 30-year financial statements and ratios for over 1,600 listed firms.

### Step-by-step setup for AI platforms

#### 1. Google Gemini Spark (Custom apps)
- **Method 1 (Recommended - Direct tokenized URL):**
  1. Open EcoData > AI Integration Portal (`/account/connect-apps`) and copy your **Direct tokenized URL**.
  2. Visit `gemini.google.com/spark/apps`, select **Add app**, and paste the URL into the **App link** field.
  3. Click **Next** to link your EcoData workspace without manual OAuth setup.
- **Method 2 (Standard OAuth 2.1 PKCE):** Enter your Client ID and Client Secret in Spark Advanced settings.
- **Prompt example in chat:** Mention `@EcoData` with natural queries:
  > *"@EcoData Retrieve Vietnam's GDP growth and registered FDI inflows from 2010 to 2025, and run an OLS regression examining the impact of FDI on GDP growth."*

#### 2. Claude Desktop
Add the MCP configuration to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "ecodata": {
      "command": "npx",
      "args": [
        "-y",
        "@ecodata/mcp-server",
        "--api-key",
        "YOUR_ECODATA_API_KEY"
      ]
    }
  }
}
```

#### 3. Cursor and Windsurf IDE
Configure `.cursor/mcp.json` or add an MCP server in editor settings:

```json
{
  "mcpServers": {
    "ecodata": {
      "url": "https://ecodata.io.vn/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_ECODATA_API_KEY"
      }
    }
  }
}
```

## Jev Co-Processor: AI inference optimization and academic verification

Applying LLMs to empirical research faces three acute hurdles: context bloat, prompt loop traps, and statistical hallucination. The **Jev Co-Processor** is a hybrid intelligence sub-system designed to eliminate these failure modes completely.

<JevCoProcessorSvg />

### Five technological pillars of Jev

1. **84.2% context token reduction (Dynamic Sub-schema Exposure):**
   Instead of exposing all 37 tools (~15,200 tokens), Jev classifies user intent in under 5ms and exposes only the 7–10 relevant tools (~1,850 tokens), drastically cutting costs and eliminating tool confusion.
2. **Loop prevention and automated input sanitization (Inbound Guardrails):**
   Automatically rectifies reversed date ranges (e.g., converting `2024 -> 2020` to `2020 -> 2024`), validates symbol strings, and routes scattered single queries into efficient batch operations.
3. **1-Click autonomous pipeline execution:**
   Orchestrates sample preparation, stationarity checking, regression, and reporting in a single execution step without repetitive confirmation loops.
4. **Three-tier academic verification standard (Unified Outbound Verifier):**
   Every analytical response is audited across three pillars before reaching the user:
   - **Tier 1 (Verifiability):** Validates raw series integrity, citation links, and identifier consistency.
   - **Tier 2 (Methodology):** Enforces Gauss-Markov diagnostic tests, flagging multicollinearity ($VIF > 5$), autocorrelation, and heteroskedasticity.
   - **Tier 3 (Consistency):** Conducts cross-runtime verification across Python, R, and Stata 18 MP. The output is approved only if parameter differences satisfy $\Delta < 10^{-6}$.
5. **Native MCP multimodal chart rendering:**
   Delivers high-resolution economic figures and regression diagnostic plots directly within the MCP stream.

## Multi-platform data retrieval toolkit

In addition to interactive web dashboards, EcoData provides official client libraries connecting through the **Public SDMX API** (`/api/v1/sdmx`):

```bash
# Install the official Python package
pip install ecodata-py
```

```python
# Query macroeconomic series via Python
from ecodata import EcoData

client = EcoData(api_key="YOUR_ECODATA_API_KEY")
df = client.series(
    flow="MACRO_INTL",
    indicator="NY.GDP.MKTP.KD.ZG",
    countries=["VNM", "THA", "MYS", "SGP"],
    start_year=2010,
    end_year=2024
)
print(df.head())
```

## Standard empirical research workflow

A 6-step empirical roadmap for researchers, graduate students, and policy analysts using EcoData:

```mermaid
flowchart TD
  A["1. Formulate research topic and hypotheses"] --> B["2. Retrieve macro/micro data via EcoData"]
  B --> C["3. Verify stationarity, clean, and inspect metadata"]
  C --> D["4. Specify econometric models in Analysis Hub"]
  D --> E["5. Execute across triple runtime (Python / R / Stata 18 MP)"]
  E --> F["6. Verify Gauss-Markov assumptions via Jev & export replication package"]
```

### Five golden principles for indicator selection

1. **Clarify unit of analysis:** Match your research question to country, province, firm, household, or individual level before downloading.
2. **Audit data coverage:** Examine missing value ratios across panels and timeframes before merging datasets.
3. **Scrutinize metadata definitions:** Confirm measurement units (current vs. constant currency, percentages, ratios) and official methodologies.
4. **Perform robustness checks:** Compare estimation results across specifications and runtime engines to ensure conclusions remain invariant.
5. **Preserve scientific replication bundles:** Retain generated `.do`, `.R`, and `.py` scripts alongside raw data pulls to guarantee 100% scientific reproducibility.
